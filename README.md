# My Bus — Home Assistant 公交到站集成（全国 · 掌上公交）

以「某线路公交车到达某站点」作为 Home Assistant 自动化触发条件的自定义集成。

- 配置方式: **7 步按钮式向导**（选择城市 → 选择检索方式 → 站台/线路 → 线路/站台 → 选择到站参数 → 数据同步 → 确认创建），**每一步都只有中文按钮**，每一步的第一个按钮都是真实的 **「⬅ 返回上一步」**（第 1 步是向导起点、没有上一步，那一页由说明区第一行的**欢迎语**占住这个位置），不是开关，也永远不会出现英文
- 数据源: 掌上公交公开查询接口（`h5.mygolbs.com`），**免注册、免 API Key**
- 覆盖范围: **掌上公交支持的全部 563 个服务城市**（向导第一步选城市）
  - 支持: 城市名中文/拼音模糊检索、**用家庭位置一键识别当前城市**
  - 支持: 中文/拼音首字母模糊搜索（`县口`、`县`、`xklz`、`xk` 均可找到「县口路站」）、站台↔线路双向联动、数字/拼音排序
- **数据一致性**: 城市 / 线路 / 站台 / 站点拓扑等结构数据本地留一份副本，**默认每 12 小时自动与掌上公交同步一次**（可调），线路改线 / 站序变化会**自动跟随**；实时到站数据永不缓存
- 数据刷新: 默认每 **10 秒**轮询一次（可在选项中调整，最小 5 秒）
- **无障碍**: 按钮文案对齐 0.3.0 的简洁风格——**emoji 前缀 + 动词短句**（如「📍 定位当前城市」「🔍 检索城市名」），**全程没有英文按钮、没有需要猜的开关**，盲人用户可以用屏幕阅读器逐项听完再操作；**每一页的第一个按钮固定是「⬅ 返回上一步」**（读屏是**用上下光标 ↑ ↓ 逐项听按钮**的，这样走错一步不用听完几百个候选项才退得回去）

## 安装

1. 将 `custom_components/my_bus` 整个文件夹复制到 Home Assistant 配置目录:
   ```
   <config>/custom_components/my_bus/
   ```
2. 重启 Home Assistant。
   1. 进入 **设置 → 设备与服务 → 添加集成**，搜索 **My Bus**。

> 安装后**无需任何手工初始化**：首次启动会自动把城市列表与已配置监控涉及的线路 / 站台数据同步下来，之后按同步间隔自动保持最新。
> 从 0.1.x 升级到 0.2.0 时，已有的厦门监控条目会自动迁移（补齐城市＝厦门市），无需重新添加。
> ⚠️ **从 0.8.4 及更早版本升级**：集成域名已由 `xm_bus` 改为 `my_bus`，**安装目录名必须是 `custom_components/my_bus/`**（HA 强制要求目录名与域名一致），装完请删除旧的 `custom_components/xm_bus/` 目录并重启 HA。

## 添加一个到站监控（7 步按钮式向导）

添加集成后是一个**一步一步的按钮式向导**，从「选择城市」到「确认创建」共 **7 步**。**每一步的界面结构与操作逻辑完全一致**：

- 顶部是**统一抬头**：`第 N 步 / 共 7 步`（只报进度，**不重复步骤名** —— 步骤名由对话框标题显示，两处都写读屏会念两遍）；
- 中部是**本步的提示与候选**：所有能点的选项都渲染成**真正的按钮**，按钮文字就是它的含义（例如 `615路（四林总站→丙洲东头尾站）`）；
- **第一个按钮固定是「⬅ 返回上一步」**（第 1 步是向导起点，没有上一步可回——它的第一行是欢迎语，见下），之后才是本步的检索 / 动作按钮与候选项（最后一步是 `✅ 完成` / `✅ 保存修改`）。

只有**需要键盘输入的两处**使用输入框：**输入检索关键词**、**修改到站参数**（以及数据同步页里的「修改同步间隔」）。其余步骤**没有任何开关、没有下拉框、没有英文按钮**。

| 步骤 | 步骤名 | 做什么 |
| ---- | ------ | ------ |
| 1 | 选择城市 | 说明区**第一行是欢迎语** `欢迎使用 My Bus，这是一个实时公交监控集成。`（第 1 步是向导起点、没有「上一步」，用一行自我介绍占住第一位，版式就与第 3 步一致了）；三个动作按钮（**顺序固定**）：`🔍 检索城市名` / `📍 定位当前城市` / `🏙 全部城市列表（共 N 个）`。**检索按钮永远排在动作组第一**，检索出的城市候选**紧跟其后**，与第 3 步的 `🔍 检索站台` / `🔍 检索线路` 版式完全一致 |
| 2 | 选择检索方式 | 只问一次「先选站台还是先选线路」，两个按钮：`🚏 先选站台`（知道站名走这条）/ `🚌 先选线路`（知道线路号走这条）。**点哪个第 3 步就是哪条路** |
| 3 | 选择站台 / 选择线路 | 站台优先 → 检索并选中一个站台；线路优先 → 检索并选中一条线路。命中的候选逐个列成按钮 |
| 4 | 选择线路 / 选择站台 | 站台优先 → 列出该站台一侧停靠的线路按钮；线路优先 → 按途经顺序列出站台按钮（`3. 县口路站`） |
| 5 | 选择到站参数 | 一个按钮 `⏱ 修改到站参数（当前：每 10 秒刷新）`；点开是**一个**数字输入框（刷新间隔）。下一个按钮是 `⏭ 下一步` |
| 6 | 数据同步 | 与选项菜单里的 `🔄 数据同步` **是同一套界面**（见下一节）：`🔄 立即同步（上次：…）` / `⏱ 修改同步间隔（当前：每 12 小时）` / `🔄 关闭自动同步`，再加一个 `⏭ 下一步`。创建监控前可以先把城市 / 线路 / 站台对齐到最新 |
| 7 | 确认创建 | 复述全部内容，两个按钮：`⬅ 返回上一步` / `✅ 完成` |

> 0.8.0 一度把第 2 步「先选站台 / 先选线路」并进第 3 步、把向导压成 5 步；0.8.1 **按要求恢复成独立的一步**（第 2 步），站台页 / 线路页上互跳的按钮也一并去掉，完全回到原来的结构。好处是每一步的「第 N 步」都名实相符——读屏用户在检索方式页听完两个入口就能选定路线，不会在站台页上又听到一个「改走线路」的按钮而犯迷糊。

**关于「上一步」**：Home Assistant 的配置流对话框**没有原生的「上一步」按钮**（头部只有关闭），但**菜单（menu）步骤可以把任意选项渲染成真正的按钮**。因此本版把每一步都做成菜单，于是每一步天然拥有一颗真实的「⬅ 返回上一步」按钮，点一下就退回上一步——不需要先打开某个开关。它固定排在**所有按钮的最前面**：读屏用户是用**上下光标（↑ ↓）逐项**听按钮的（Tab 在配置流里会跳出当前列表，见下文「键盘操作」），「全部城市列表」那页有几百个候选项，返回若排在最后就得听完整个列表才够得到。第 1 步是向导起点，没有上一步。

**关于「不会出现英文按钮」**：菜单按钮上的文字由集成**直接写在代码里**、**不经过 Home Assistant 的翻译层**，所以无论 HA 界面语言是什么，看到的都是中文；同时 `strings.json` / `translations/zh-Hans.json` / `translations/en.json` **三份文案内容完全相同、全部是中文**，即使 HA 回退到英文语言包也仍然是中文界面。输入框的字段名同样用中文文本做键（例如 `城市名关键词（中文、拼音或首字母）`），翻译万一失效时显示的也是中文而不是英文的字段代码。

各步细节：

1. **选择城市**（版式与第 3 步一致：**第一行是欢迎语 / `⬅ 返回上一步`，第二行才是检索按钮**，候选紧跟其后，读屏用户换步不用重新找位置）
   - 说明区**第一行是欢迎语** `欢迎使用 My Bus，这是一个实时公交监控集成。`（0.8.4）。它只在**向导第 1 步的落地页**出现一次：进到第 1 步的两个子页（`🔍 检索城市名` 的输入框、`🏙 全部城市列表`）或从选项流进来改城市，都不会再重复念一遍；
   - `🔍 检索城市名`（**排在动作组第一个**，与第 3 步的 `🔍 检索站台` / `🔍 检索线路` 对齐）：支持中文子串（`厦门`、`厦`）与拼音（`xiamen`、`xm`）；**只命中一个时直接采用**，命中多个则回上一屏、把候选**列在检索按钮正下方**；
   - 之后才是另外两个动作按钮：`📍 定位当前城市` / `🏙 全部城市列表（共 N 个）`；
   - `📍 定位当前城市`：读取 Home Assistant 家庭位置（设置 → 系统 → 通用 → 位置），用坐标反查所在城市（`CMD108`，**不依赖任何第三方地图服务**），再自动匹配到服务城市列表里的正式名称。接口偶发抖动时集成会**自动退避重试**；确实不在服务范围内（如境外坐标）才提示「不在掌上公交的服务范围内」，重试仍失败则提示稍后重试（不会误报成「不在服务范围」）；
   - `🏙 全部城市列表（共 563 个）`：把全部服务城市列成按钮（按钮上直接写着总数，读屏用户不必点进去才知道有多少个；数量受 HA 限制，建议优先用关键词检索）；
   - 想同步数据不用在这一页找按钮：**同步是向导第 6 步「数据同步」**（0.8.9 起），与选项菜单里的同名入口是同一套界面。
2. **选择检索方式**：只问一次「先选站台还是先选线路」，两个按钮 + `⬅ 返回上一步`：
   - `🚏 先选站台`（知道站名走这条）/ `🚌 先选线路`（知道线路号走这条）；
   - 提示一句话说明区别：`先选站台然后选择停靠线路，或先选线路然后选择途经站台。`；
   - 选了哪个，第 3 步就是哪条路；中途改主意可以点「上一步」回来重选（改选会把之前选的站台 / 线路 / 方向一并作废，避免串线）。
3. **选择站台 / 选择线路**（两条路各占一步）
   - `🔍 检索站台` / `🔍 检索线路`（**排在动作组第一个**）：打开输入框，键入关键词后候选**就地列成按钮**（结果过多时接口只返回前 30 条，**界面上会明确提示这一点**，可多加一个字收窄）。输入框都是**可选字段**，留空提交即返回本页。
   - **只命中一个时直接采用**，不必再点一次；站台搜索结果**每个站名只出一条**（与掌上公交一致，不按方向重复）。
4. **选择线路 / 选择站台**
   - **站台优先**：列出该站台一侧停靠的线路按钮（形如 `618路（梧侣公交场站→方特旅游区站）`）；另有 **`🔄 反向站台`** 按钮，点一下即切到马路对面那一侧的线路；
   - **线路优先**：只列出**该线路经过的站台**，按**途经顺序**编号（`3. 县口路站`），每个站台只对应一个方向；提示只说这条线路途经多少站，并用**真实起终点**标注方向（`线路「615路」（四林总站→丙洲东头尾站）途经 32 站。`），比「上行 / 下行」好认。
5. **选择到站参数**：说明区是一句 `选择刷新频率。`；一个菜单按钮显示当前参数，点开是**一个数字输入框**（说明区只写 `输入数字。`），**字段名自带范围与单位**：`数据刷新间隔（秒，范围 5 到 120）`（默认 10）。保存后回到本步并显示「已保存」，按钮文字同步更新。**0.9.1 起「提前多少站 / 多少公里」已移除**——到站事件只看车辆是否真的抵达监控站台，不再有提前量。
   - **两个提醒都始终生效，没有「关闭」**：站数 `1`～`5` 站、里程 `0.1`～`20` 公里，谁先满足就按谁触发（同时满足时记「站数」）。
   - **后端也会夹取越界值**：前端输入框已经限制范围，后端再兜一层（`0` 秒会变成 `5` 秒、`9999` 秒封顶 `120` 秒、`99` 站封顶 `5` 站、`9999` 公里封顶 `20` 公里），旧条目 / 手工改过 `.storage` 的数据也不会把协调器带进忙轮询。
   - **为什么没有 `0` 公里**：`0` 原来表示「不按距离提醒」（关闭距离提醒）。0.7.0 把它去掉了，里程从 `0.1` 公里起——**距离提醒永远生效**。旧条目里存的 `0` 会被当作默认值 `1` 公里处理（见「版本历史 0.7.0」）。
6. **数据同步**（0.8.9 新增的一步）：**与选项菜单里的 `🔄 数据同步` 是同一套界面**，所以学会一处就会这一处：
   - 说明区第一行是这一步特有的开场白 `创建前可以先把数据同步到最新。`，然后是同步状态（上次同步时间 / 自动同步开没开 / 本地缓存规模 `城市 N / 线路 N / 站台 N`）；
   - 三个动作按钮：`🔄 立即同步（上次：…）`（点完就在本页显示结果，例如 `同步完成：城市 563、线路 2、站台 3。`；**有失败项时不报数字**，只说明失败原因）、`⏱ 修改同步间隔（当前：每 12 小时）`（数字输入框，1～168 小时）、`🔄 关闭自动同步`（关闭后同一位置变成 `🔄 启用自动同步`）；
   - 不想改就直接点 `⏭ 下一步` 进入最后一步。**这一步本身不会写进监控配置**，改的是全局同步设置（与选项菜单里改的是同一份）。
7. **确认创建**：说明区是一句 `请确认配置`，下面逐行列出城市 / 站台 / 线路 / 方向（起终点）/ 刷新间隔 / 自动同步（0.9.5 起补上：`每 N 小时` / `已关闭` / `未启用`，是全局同步设置的展示），点 `✅ 完成`。
   - 创建前会校验站台确实在该线路方向上；若接口暂时不可用、或站台已不在该线路上，**仍停留在本步并给出中文提示**（不会中断流程），点 `⬅ 返回上一步` 即可回去修改。

同一「城市+线路+方向+站台」不允许重复添加；可添加多条监控。

## 修改已创建的监控（选项）

进入 **设置 → 设备与服务 → My Bus → 配置**（齿轮），先看到按钮式入口菜单；选择某一项后进入的就是**添加时那套同样的向导步骤**，只是「上一步」的终点变成了这个菜单（按钮显示为 `⬅ 返回选项菜单`）：

- **🌆 修改城市（当前：…）** —— 从**第 1 步「选择城市」**进入向导（三个按钮完全一致）。**改城市后会强制重新选择线路与站台**（不同城市的线路站台不通用）。
- **🔁 修改线路 / 站台（当前：…）** —— 从**第 2 步「选择检索方式」**进入向导，重新走一遍站台 / 线路选择，选完直接到确认页（跳过参数页），点 `✅ 保存修改` 写回并自动重载。
- **⏱ 修改到站参数（当前：…）** —— 从**第 5 步**进入，直接打开刷新间隔数字输入框，点提交即写回；**改完立刻生效**（条目会自动重载一次）。
- **🔄 数据同步（N 城市 / N 线路 / N 站台）** —— 与**向导第 6 步「数据同步」**共用同一套界面（同一个 `step_id`、同一批按钮），只有说明区的开场白不同（这里讲缓存规模）。三个动作按钮：`🔄 立即同步（上次：…）`、`⏱ 修改同步间隔（当前：每 12 小时）`、`🔄 关闭自动同步`（关闭后同一位置变成 `🔄 启用自动同步`）。详见下一节。
- **✅ 完成** —— 结束，不修改任何内容。

> 修改线路 / 站台时会先校验站台确实在该线路方向上，成功后才写回；若接口暂时不可用会给出中文提示，不会改动现有配置。

## 数据同步（与掌上公交保持一致）

集成里的城市 / 线路 / 站台 / 站点拓扑都不是写死的，而是**从掌上公交实时取回并本地留一份副本**，再定期与线上对齐：

| 数据 | 来源 | 缓存有效期 | 说明 |
| ---- | ---- | ---------- | ---- |
| 城市列表 | `CMD101` | 7 天 | 每次同步强制刷新 |
| 线路站点拓扑（含站序） | `CMD103` | 7 天 | 每个已配置监控涉及的线路 / 方向 |
| 站台停靠线路 | `CMD115` | 24 小时 | 只存静态结构，**不含**到站预览 |
| 线路起终点 | `CMD114`（全量） | 24 小时 | 用于把线路标签补成 `615路（四林总站→丙洲东头尾站）` |
| 实时到站 | `CMD104` / `CMD115` | **不缓存** | 永远实时请求 |

**自动同步**（默认每 12 小时，可调 1～168 小时或关闭）会：

1. 刷新城市列表；
2. 刷新**所有已配置监控**涉及的线路拓扑、站台线路与线路起终点；
3. **校对已配置监控**：掌上公交调整站序时**自动修正**条目的站序并重载（实时判定立刻跟着变）；站台被挪到另一方向或已不在线路上时，在同步状态里记为「不一致」并写日志，**不擅自改动你的配置**；
4. 清理长期未使用（30 天）且不属于已配置监控的缓存条目。

缓存存放在 `<config>/.storage/my_bus.data`（HA 标准存储，重启后仍在），并会自动裁剪、原子写入。

**查看同步状态**：

- 每个监控设备下有一个诊断实体 **`sensor.…_数据同步`**，状态是上次同步完成时间，属性含同步间隔、缓存规模（城市 / 线路 / 站台数）、失败次数与不一致清单；
- **设置 → 设备与服务 → My Bus → 下载诊断** 里可拿到完整的同步状态与缓存键清单。

**手动触发同步**（两种方式，走的都是同一条路径）：

- 向导**第 6 步「数据同步」**里的 `🔄 立即同步`；
- 选项菜单里的 `🔄 数据同步（N 城市 / N 线路 / N 站台）` → `🔄 立即同步`；
- 或直接调服务（0.9.4 起设备页不再有「立即同步」按钮）：

```yaml
action: my_bus.sync_data
data:
  city: 厦门市          # 可选，只同步该城市的监控；不填则同步全部
response_variable: sync_result
```

放在自动化里定期执行也可以，例如每天凌晨同步一次：

```yaml
automation:
  - triggers:
      - trigger: time
        at: "03:30:00"
    actions:
      - action: my_bus.sync_data
```

## 设备页能看到的实时信息

每条监控会以一台**设备**的形式出现（如 `My Bus（厦门市 615路 县口路站）`）。
在 **设置 → 设备与服务 → 设备** 里点开它，实体列表中除了「数据同步」，还会有四个**实时到站**传感器
（都只看**离监控站台最近的一辆车**）：

| 实体 | 状态示例 | 说明 |
| --- | --- | --- |
| **剩余站数** | `3 站` | 最近一辆车到监控站台还剩几站 |
| **剩余公里数** | `1.3 公里` | 还剩多少**线路里程**（保留 1 位小数）；接口没给分段里程时显示「未知」 |
| **预计到达** | 官方分钟数 / `预计发车:11:00` / `N站` / `等待发车` / `暂无数据`（0.9.7 起无分钟数时显示官方原文，永远有状态） | **纯官方**：CMD115 的「N分钟」；官方「已到站」→ 0 分钟；车未发出 → 官方「预计发车 HH:MM」原文 |
| **到站状态** | `未到站` / `即将到站` / `已到站` | **0.9.2 起按官方口径三态**：`已到站` = 接口确认车辆**正停在站上**（`statusType=0`）；剩 0 站但车还在途 = `即将到站`；其余 `未到站` |

当前没有在途车辆时，站数 / 公里数 / 分钟为**未知**、状态显示 `暂无车辆`。
每个实体的属性里还有**车牌、当前站、剩余站数、剩余公里数、线路、方向、官方原文**等明细 —— 点开实体就能看到，
也能在自动化里用 `trigger.to_state.attributes.<名字>` 取用。

> **0.9.27 起属性名全部用中文**（`城市`、`线路`、`站台`、`方向`、`车牌`、`当前站`、`剩余站数`、
> `内部剩余站数`、`剩余距离米`、`剩余公里数`、`预计到达分钟`、`预计到达来源`、`官方原文`、
> `官方剩余距离`、`到站状态`；数据同步实体为 `是否启用`、`刷新间隔小时`、`上次同步`、`耗时秒`、
> `城市数`、`线路数`、`站台数`、`失败次数`、`最后错误`、`问题`、`距上次同步小时数`）。
> 原因：HA 的「状态已变化」触发器里那个「属性（可选）」下拉框，显示的就是属性键本身
> （下划线换成空格、首字母大写），没有任何翻译层——想让用户看到中文，只能把键名写成中文。
> 副作用：0.9.26 及以前写过的模板如果按英文属性名取值（如 `state_attr(...,'plate')`），
> 升级后要改成新名字。

> 刷新频率与到站判定一致（默认 10 秒一轮），所以设备页上的站数与分钟会跟着实时变化。

## 在自动化中使用

每条监控会以一台**设备**的形式出现（`My Bus（厦门市 615路 县口路站）`），设备下挂着六个传感器实体（剩余站数、预计到达、剩余公里数、车牌、到站状态、数据同步），并在自动化编辑器里提供 **9 个触发器** 与 **9 个条件**，按实体一对一挂载（每个实体页只显示属于自己的那几条）。

### 一、触发器：添加触发条件 → 按设备（或按实体）

| 触发器 | 挂在 | 什么时候触发 |
| ------ | ---- | ------------ |
| **已到站 / 即将到站 / 未到站 / 暂无车辆** | 到站状态 | 状态**变成**该状态的那一刻（官方文案口径，0.9.19 起严格对齐掌上公交 App） |
| **剩余站数变化** | 剩余站数 | 站数变化时触发，可选「任意变化 / 高于 / 低于 / 区间」，单位：站 |
| **剩余公里数变化** | 剩余公里数 | 同上，单位：公里（支持 1 位小数） |
| **预计到达变化** | 预计到达 | 同上，单位：分钟 |
| **数据同步完成** | 数据同步 | 一次结构数据同步完成时触发 |
| **车牌变为** | 车牌 | 车牌变成**填写的号码**时触发（手填车牌号）；可加通配符 `*`（任意多个字）/ `?`（一个字），如 `闽D06*`；首班车恰好符合也算（0.9.29，通配符 0.9.30）。填 `*` = 监控任意车辆出现（0.9.31 起它取代了「车牌变化 / 换车」两条，这两条已删除） |

### 二、条件：添加条件 → 按设备（或按实体）

| 条件 | 挂在 | 判什么 |
| ---- | ---- | ------ |
| **已到站 / 未到站 / 即将到站 / 暂无车辆** | 到站状态 | 此刻**是不是**该状态（精确匹配，不是取反），支持「持续至少」 |
| **剩余站数** | 剩余站数 | 此刻站数 高于 / 低于 / 区间 / 等于，单位：站 |
| **剩余公里数** | 剩余公里数 | 同上，单位：公里（支持 1 位小数） |
| **预计到达** | 预计到达 | 同上，单位：分钟 |
| **数据同步** | 数据同步 | 距上次同步已过去的小时数（高于 / 低于 / 区间 / 等于，单位：小时）；从未同步过则**不成立** |
| **车牌变为** | 车牌 | 此刻最近一辆车的车牌符合**填写的号码**（手填车牌号，与触发器同名）；可加通配符 `*`（任意多个字）/ `?`（一个字），如 `闽D06*`；**没车时不成立**（0.9.28 首版叫「车牌是」，0.9.32 改名与触发器一致并删除「车牌不是」，通配符 0.9.30） |

**触发器与条件的区别**：触发器是「变化的那一刻」；条件是「执行到这一步时，此刻是否满足」。同一个数值两边都有，语义不同。两者的「持续至少 / 条件满足如果」字段都在界面上，不用改 YAML。

> 「按实体」栏里还会列出核心自带的「状态 / 数值状态已跨越阈值 / 属性」——那是 HA 前端按实体域生成的通用项，与本集成无关（任何 `sensor` 实体下面都有）。到站状态是文本状态，配核心「数值状态」永远不成立（还会刷日志警告），请用本集成的四条状态触发器/条件；数值三项用本集成带单位的版本更直观。

> 数值类与数据同步类条件都不依赖设备在线：传感器为「未知 / 暂无数据」时条件判为**不成立**，不会被当成 0。

> **车牌**（0.9.28 起单独成实体）：状态就是车牌号，没车时显示「未知」。它是文本实体，所以只有「状态」类触发器和条件，没有「高于/低于」。此前车牌只是「到站状态」的一个属性，现在属性仍然保留（老模板的 `state_attr(…, '车牌')` 不受影响），另多了一个可以单独选中的实体。

## AI / 语音调用

集成注册了可被 AI 助手、语音管道或其他自动化调用的服务:

## 无障碍

本版（0.5.0 重设计、0.5.1 按 0.3.0 风格精简文案、0.5.x 持续微调、0.8.0 按读屏习惯微调顺序与去重、0.8.1 恢复 6 步结构、0.8.2 修步号错位、0.8.3 去掉重复朗读并补检索截断说明、0.8.4 第 1 步加欢迎语并把集成改名为 My Bus、0.8.5 域名改为 `my_bus`、0.8.6 设备型号去掉城市前缀、0.8.7 设备页实时到站、0.8.8 剩余公里数与「立即同步」按钮、0.8.9 向导插入第 6 步「数据同步」、0.9.0 按钮版式统一并精简全流程文案、0.9.1 移除提前站数/公里参数）的核心目标是：**不看屏幕也能凭朗读把监控配好**，并能在自动化里用中文念出的触发器挑条件。

- **全程没有英文按钮**。所有按钮文字都由集成直接写在代码里、**不经过 HA 的翻译层**，因此无论 HA 界面语言是什么都显示中文；同时三份语言文件（`strings.json` / `translations/zh-Hans.json` / `translations/en.json`）**内容完全相同且全部是中文**——即使 HA 回退到英文语言包，界面仍是中文。输入框的字段名也用中文文本做键（如 `城市名关键词（中文、拼音或首字母）`），翻译万一失效时显示的仍是中文而不是英文代码。
- **每一页的第一个按钮固定是 `⬅ 返回上一步`**（0.8.0）。菜单项是真正的按钮，读屏**用上下光标（↑ / ↓）逐项移动并朗读**，而 `🏙 全部城市列表` 那一页有几百个候选项——「返回」若排在最后，走错一步就得把整个列表听一遍才退得回去。放在第一位后，**按一次 ↓ 就能听到「返回」**。导航按钮在前也符合浏览器「返回」的直觉。
  - **键盘操作（多款读屏实测，0.9.32 文档修订）**：逐项浏览候选项请用**上下光标**；**不要用 Tab 逐项切换**——在 HA 的配置流对话框里按 Tab 会从当前列表里跳出去（落到对话框的其它控件、甚至离开选择城市这个界面），这是 Home Assistant 配置流对话框本身的焦点行为，集成侧无法改变。Tab 只适合「从列表跳到整页的其它按钮」，例如在长列表末尾按 Tab 找到`⬅ 返回上一步`（它排在第一位，所以多数情况直接按 ↑ 更快）。
  - 第 1 步是**向导起点**、没有「上一步」可回，所以它的**第一行是欢迎语**（`欢迎使用 My Bus，这是一个实时公交监控集成。`，0.8.4）。这样第 1 步与第 3 步的版式一致：**第一行都不是检索按钮，检索按钮都排在第二行** —— 读屏用户换一步不用重新找位置。
- **按钮就是菜单项，不再有开关**。0.4.0 曾经用开关表达「上一步 / 定位 / 同步 / 反向站台」，读屏只会念出「开关 未选中」，用户不知道它干什么。本版把这些**全部改成 emoji 前缀 + 动词短句的按钮**（风格与 0.3.0 一致、长度减半）：
  - `⬅ 返回上一步`（每一步都有真实的「上一步」按钮，不需要先打开开关再点提交）
  - `🔍 检索城市名`、`📍 定位当前城市`、`🏙 全部城市列表（共 563 个）`（**检索按钮固定在动作组第一位、候选紧跟在它正下方**，与第 3 步的 `🔍 检索站台` / `🔍 检索线路` 版式一致；「全部城市列表」按钮上直接写着总数，不必点进去才知道有多少个。**0.8.9 起「同步最新数据」不再放在这一页**——同步挪到了向导第 6 步）
  - `🚏 先选站台` / `🚌 先选线路`（第 2 步「选择检索方式」，二选一决定后面走哪条路）
  - `🔍 检索站台` / `🔍 检索线路`（第 3 步按上面选的那条路，打开对应的关键词输入框）
  - `🔄 反向站台`
  - `⏱ 修改到站参数（当前：每 10 秒刷新）`
  - 候选按钮直接就是城市名 / 站台名 / 线路名（`615路（四林总站→丙洲东头尾站）`、`3. 县口路站`），读屏按顺序念就是一列可选项。
- **emoji 只是装饰，文字永远完整**（0.8.0 明确下来的规则）。按钮上的图标**保留**——现代读屏对 emoji 基本是跳过或只念一次名称，不影响理解；而对普通用户，前缀图标是「一眼找到按钮」最快的线索（🔍 检索 / ⬅ 返回 / 🔄 同步 / ⏱ 参数 / ✅ 完成）。约束只有三条：① emoji **只能出现在最前面**，不许夹在句子中间；② 去掉 emoji 后必须**还剩一句完整的中文**，绝不允许「只有图标没有文字」的按钮；③ **同类动作共用同一个图标**，读屏用户听到开头一两个字就知道这是什么按钮。回归里 `I19` / `I19b` / `I19c` 守着这三条。
- **不做无意义的重复朗读**（0.8.0 起，0.8.3 补齐）。对话框标题**只写步骤名**（`选择城市`），进度 `第 N 步 / 共 7 步` 只在说明区出现一次——原先标题写「第 1 步 · 选择城市」、说明区又写一遍，读屏要听两遍；**0.8.3 又把说明区里残留的「· 步骤名」去掉**（否则读屏会念成「选择站台 …… 第 3 步 / 共 7 步 · 选择站台」）；第 5 步的说明区也不再重复按钮上已经写着的当前参数，参数表单的说明不再重复字段名里的取值范围。
- **文案以短句为主**。提示通常只有一句话（`与「同安」匹配的站台 2 个。`），确认页才把全部内容列清楚，不再每页罗列已选摘要——读屏不必听完一大段重复。
- **错误与提示都在原位用中文说明**。例如 `没有找到与「火星市」匹配的城市。`、`站台「××站」不在线路「615路」上，请返回重新选择。`——不会中断流程跳到莫名其妙的页面。
- **「上一步」永远指回真正的来路**。向导会记录用户实际走过的步骤，所以在选项流里「改线路」跳过参数页时，确认页的「⬅ 返回上一步」仍会退回刚才选的线路（而不是一个从没见过的「选择到站参数」）。
- **按键输入的地方只有两处**，字段名**本身就是中文**，括号里直接写着范围与单位，读屏念出来就是一句范围提示：
  - 检索关键词：`城市名关键词（中文、拼音或首字母）` / `线路关键词（线路号或名称）` / `站台名关键词（中文、拼音或首字母）`
  - 到站参数：`数据刷新间隔（秒，范围 5 到 120）`（0.9.1 起是唯一字段）
  - 这些字段除了前端限制，**后端还会再夹一次范围**（0.8.0），越界值不会存进条目。
- **字段名故意用中文做键**（`data` 里不再放英文 key）。HA 的表单标签平时走翻译文件，但集成交付/升级后翻译不一定立刻刷新——那时 HA 会把字段的**内部名字原样显示出来**（曾经就显示成 `arriving_distance`）。写成中文则无论翻译新旧都显示中文。
- **自动化里的触发器名称也是中文**（`公交到站`），读屏念出来就是一句能听懂的话（0.9.1 起条件类型已随阈值触发器一并移除）。
- 所有界面都是 Home Assistant 原生配置流控件，自动继承 HA 的屏幕阅读器标签、焦点管理与键盘操作。
- 实体命名遵循 HA `has_entity_name` 规范，设备名形如 `My Bus（厦门市 615路 县口路站）`，事件实体名「公交到站」，便于语音与读屏软件定位。
- **数据同步状态**是设备下的一个诊断实体（名称「数据同步」），状态为上次同步时间、属性为缓存规模与问题清单，读屏软件可直接朗读。
- 回归测试里专门有一组断言守着这些无障碍约束（`tests/verify_v091.py` 的 `[A]`/`[I]`/`[X]` 分组）：每一页第一个按钮是「上一步」（第 1 步由欢迎语占位）、每一步的抬头（`第 N 步 / 共 7 步`，**不含步骤名**）、页面里**不出现任何开关控件**、按钮是**emoji + 动作词**的短句、**emoji 只当前缀且去掉后仍有完整中文、同类动作图标统一**、**三个「🔍 检索…」按钮落在整页的同一个位置**、步骤标题不含「第 N 步 ·」且不含数字、文案表里没有死键、`en.json` 的每一句都含中文。

## 技术说明

- **城市**来自 `CMD=101`（实测 565 条，清洗掉 `厦门市测试`、`厦门市1` 这类脏数据后 563 条）。
- **识别当前城市**用 `CMD=108`（POST `LAT` / `LNG` / `MYLAT` / `MYLNG`，四者取同一个家庭坐标 —— `LAT/LNG` 是被反查的坐标，`MYLAT/MYLNG` 是「我的位置」，官方 H5 页面会一起发，实测四者齐全时命中率略高）：把家庭坐标发给掌上公交，接口直接返回所在城市名（如 `厦门市`），再与服务城市列表做「完全相同 → 去后缀相同 → 互相包含」三级匹配。**不需要任何第三方逆地理编码服务**（Nominatim 在国内会被 Cloudflare 拦截，因此没有采用）。该接口实测存在**服务端抖动**（同一坐标连发 6 次常有一半左右返回 `{"status":-1}`，换请求头、带 Cookie、拉长间隔、微抖坐标都不改善），因此客户端**退避重试最多 6 次**：拿到 `status=1` 返回城市名，拿到 `status=2`（实测境外坐标如此）才认定「确实没有服务城市」返回 `None`，重试耗尽则抛 `XmBusApiError` 让界面提示「稍后重试」——避免把一次接口抖动误报成「你的位置不在服务范围」。
- 所有业务命令都带 `CITYNAME`，所以客户端按城市实例化并在 `hass.data["my_bus"]["client::<城市>"]` 里复用。
- **数据同步层**（`data_sync.py`）统一封装结构数据的本地缓存：所有读写都带 TTL，过期即按需拉取；定期同步任务（`async_track_time_interval`）在后台运行，完成后把 `generation` 自增，协调器据此在下一轮轮询时重新读取线路拓扑 —— 因此掌上公交改线后**不需要重启或重新配置**。同步任务在**最后一个监控被删除**时自动停止并落盘。
- 到站判定采用**几何位置模型**: 轮询获取全线每辆车的实时站序，`剩余站数 = 目标站序 - 车辆当前站序`（环线自动取模绕回）。经实测校准，比直接依赖接口的 arrive/come 标志可靠。
- **「剩余公里数」也用同一套数据算出来**（`CMD=104` 实测字段）：`list[].busToStationNiheDistance` 是**车 → 即将到达站**的线路里程（米），`list[].index` 是「即将到达站的站序 − 1」（`stationName` 就是那一站），`dislist[].d[i]` 是**第 i+1 站 → 第 i+2 站**的分段里程（米，末项通常为 0，长度与线路站数相同）。于是
  `车到监控站的里程 = busToStationNiheDistance + 从「即将到达站」到监控站之间的各段 dislist 之和`（还差 d 站就加 d 段）。
  取的是**线路里程**而不是直线距离（实测同一对站点，线路里程 / 直线距离 ≈ 1.0～2.0，符合公交绕行）；已过站且非环线则视为不参与（返回未知，不给负数）；万一接口没带 `dislist`，只有「车正驶向监控站」那一刻能给出确切里程，其余情况按未知处理（只按站数判定，不受影响）。
- **到站判定**（0.9.2 起）：按**官方口径** —— CMD104 每辆车的 `statusType`（`"0"`=正停在站上 / `"2"`=在途）。车辆「剩余站数 == 0 且官方确认停站」时发一次「到站」事件，事件里带上当时的里程；接口没给 `statusType` 时退回「剩余站数 == 0」的老口径。「即将到站」（剩 0 站但在途）不再误报为已到站。原先按站数 / 里程的提前触发与 `reason` 字段已随 0.9.1 移除。
- 目标站的站序以**线路拓扑（掌上公交数据）为准**：协调器每次读取拓扑时都会用最新的站序覆盖条目里的旧值，避免改线后误触发。
- 「到站」在车辆停靠目标站时触发一次，车走后可再次触发（0.9.1 起只此一种事件；原先的「即将到站」与两个「少于指定值」触发器已随提前量一起移除）。
- 接口偶发风控/网络错误时协调器进入重试，不影响已配置自动化；定期同步的失败会累加在同步状态里，便于排查。

## 已知限制

- 城市共有 563 个。「🏙 全部城市列表」会把它们全部列成按钮，一屏放不下时需下滑翻找，**建议优先用 `🔍 检索城市名`**（支持中文 / 拼音 / 首字母）或 `📍 定位当前城市`。
- `CMD108`（坐标反查城市）存在服务端抖动：同一坐标连发 6 次常有一半左右返回 `{"status":-1}`。集成会**退避重试最多 6 次**；重试仍失败时提示「稍后重试」而不是「不在服务范围」。若连续多次点 `📍 定位当前城市` 都失败，可直接用关键词检索城市。
- 定位到的是「地级市」（例如在武夷山会返回 `南平市`），若该地级市不在服务列表里，界面会提示但仍允许强行使用。
- 搜索接口单次最多返回约 30 条匹配；关键词过宽时请补充更多字。
- 数据源为掌上公交公开接口，非官方开放平台协议，若公交企业未来开放正式 API，建议迁移。
- 环线（首末站同名）按绕行圈数取模判定；极端调度（区间车、掉头）可能出现个别误触发。
- 结构数据默认 12 小时同步一次（可在选项里改），因此**改线后最长约 12 小时**（或点一次「立即同步」）才会跟上；实时到站不受影响。
